# 【第1巻】年上の部下との最初の面談は、方針を語らず「得意なこと」と「負担なこと」を聞く

## いま、こんな場面にいませんか

初めて管理職になった。チームには、10歳上のベテランがいる。
最初の面談に向けて、チームの方針や自分の考えを準備した。話し始めると、相手は腕を組み、「はい」とだけ返す。

面談は予定どおり30分で終わった。けれど、始まる前より距離が開いた気がする。

## このnoteが向いていない人

- 年下の部下も含めた、面談の進め方全般を知りたい人
- 人事評価のための面談を控えている人
- 部下のハラスメントや重大な規律違反に悩んでいる人。人事や相談窓口に相談してください

このnoteが扱うのは、**年上の部下との最初の面談の工程だけ**です。

――――――― ここから有料 ―――――――

## 結論

最初の面談の目的は、方針を伝えることではありません。**相手の経験を、自分が知ること**です。
聞くのは2つだけ。**「得意なこと」と「今の仕事で負担に感じていること」**です。

年上の部下にとって、年下の上司から最初に方針を聞かされるのは、自分の経験を飛ばされたように感じやすい場面です。先に相手の話を聞けば、「この人は自分を知ろうとしている」と受け取ってもらえます。方針は、2回目以降で十分に伝えられます。

## 手順

1. **面談の冒頭で、「今日は〇〇さんのことを教えてほしい」と目的を伝える。**
2. **「これまでの仕事で、得意だと思うこと」を聞く。**
3. **「今の仕事で、負担に感じていること」を聞く。**
4. **聞いた内容を、相手の前でメモに書く。**
5. **最後に、来月もう一度15分の面談を約束する。**

手順4を相手の前で書くのは、聞いた内容を大事に扱っていることが伝わるからです。後で「言ったのに覚えていない」と思われるのも防げます。

手順5の次回の約束は、1回で関係を作ろうとしないためです。最初の面談は、聞くだけで終わって構いません。

聞いた「得意なこと」は、次の役割分担でそのまま使えます。「負担に感じていること」は、管理職として最初に手を付けられる改善の候補になります。どちらも、面談の後の行動につながる情報です。

## つまずきやすい箇所と、その場での対処

**「特にないよ」と言われる**
→ 具体的な仕事を挙げて聞き直します。「〇〇の案件では、どこを担当されていましたか」と聞くと、得意なことが話の中に出てきます。

**前の上司への不満が出てくる**
→ 否定も同調もせず、「では、これからはどうなると働きやすいですか」と、これからの話に移します。

**自分の方針を話したくなる**
→ 次回に回します。メモの最後に「次回、方針を共有」と書いておけば、忘れません。

**敬語をどこまで使うべきか迷う**
→ 敬語は崩さずに話します。敬語を使っても、上司としての立場が下がるわけではありません。

## そのまま使える文例とテンプレート

**冒頭の一言**

> 今日は、〇〇さんのことを教えていただきたくて時間をもらいました。これまでのご経験を、チームの進め方に生かしたいと思っています。

**質問**

> これまでの仕事で、ご自分で得意だと思うのはどんなことですか。
> 今の仕事で、負担に感じていることはありますか。

**面談メモの型**

| 項目 | 内容 |
|---|---|
| 得意なこと | 取引先との条件交渉、過去の案件の経緯 |
| 負担に感じていること | 週次報告の作成に時間がかかる |
| 次回 | 〇月〇日 15分(方針を共有) |

## 次に困ること

得意なことが分かると、次はどの仕事をどこまで任せるかを決める場面が来ます。任せたつもりが放任になったり、確認したつもりが干渉に受け取られたりしがちです。
年上の部下への任せ方は、続編で扱います。

# 【第2巻】年上の部下には「任せる範囲」と「報告してほしい場面」をセットで渡す

## いま、こんな場面にいませんか

ベテランの部下に、ある案件を任せた。経験のある人だから、口出しはしないでおこうと決めた。
2週間後、自分の上司から「あの件、どうなってる?」と聞かれる。答えられない。

慌てて部下に進捗を聞くと、「任せたんじゃなかったの」と、不機嫌な顔をされた。

## このnoteが向いていない人

- チーム全員の業務の割り振りを、一から設計したい人
- 人事評価の目標設定の方法を知りたい人
- 年上の部下と、まだ最初の面談をしていない人(別のnoteで扱います)

このnoteが扱うのは、**年上の部下に仕事を任せるときの、範囲の決め方の工程だけ**です。

――――――― ここから有料 ―――――――

## 結論

任せることと、報告をもらうことは、矛盾しません。
**任せる範囲と、報告してほしい場面を、最初に同時に決めて渡してください**。最初に決めておけば、途中で報告を求めても、干渉ではなく約束の確認になります。

年上の部下が不機嫌になるのは、報告を求められたからではありません。任されたと思っていたのに、後から条件が足されたと感じるからです。条件は、任せる時点で全部出しておくことが大切です。

## 手順

1. **任せる仕事について、相手が一人で決めてよい範囲を1文で書く。**
2. **報告してほしい場面を、3つまで決める。**
3. **範囲と報告の場面を、相手に1回で伝える。**
4. **相手の意見を聞いて、範囲を調整する。**

手順2の報告の場面は、「期限に遅れそうなとき」「金額が〇万円を超えるとき」「取引先から苦情があったとき」のように、起きたら分かる形で決めます。「何かあったら」では、相手は判断できません。

手順4で相手の意見を聞くのは、範囲を一方的に決めないためです。ベテランほど、どこで判断が必要になるかを知っています。
相手の提案で範囲や場面を変えたら、その場で表を書き直して渡します。一緒に決めた形になれば、報告は相手にとっても自分の約束になります。

## つまずきやすい箇所と、その場での対処

**報告してほしい場面が、いくつも思い浮かぶ**
→ 3つまでに絞ります。多すぎると、任されたと感じてもらえません。

**相手に「全部任せてほしい」と言われる**
→ 「私が上に説明しなければならない場面だけ、教えてください」と理由を伝えます。相手を疑っているのではなく、自分の役目のためだと分かれば、受け入れてもらいやすくなります。

**決めた場面なのに、報告が来ない**
→ 責めずに、場面の決め方が分かりにくくなかったかを一緒に見直します。

**相手の方が、その仕事に詳しい**
→ 任せる範囲は、むしろ広くして構いません。報告の場面だけは必ず決めます。

## そのまま使える文例とテンプレート

**任せるときの伝え方**

> この案件は〇〇さんにお任せします。取引先との進め方は、〇〇さんの判断で決めてください。
> 3つの場面だけ、私に教えてください。期限に遅れそうなとき、金額が50万円を超えるとき、取引先から苦情があったときです。

**範囲と報告の場面の表**

| 項目 | 内容 |
|---|---|
| 任せる仕事 | A社の新規案件 |
| 一人で決めてよい範囲 | 取引先との日程・進め方・資料の内容 |
| 報告してほしい場面 | 期限に遅れそうなとき/金額が50万円超/苦情があったとき |

## 次に困ること

大きな仕事は任せられるようになりました。けれど、日々の細かい依頼が、どうしても頼みにくい。年上の相手に急ぎの仕事を頼むとき、つい遠慮した言い方になってしまう。
年上の部下への依頼の仕方は、続編で扱います。

# 【第3巻】年上の部下への依頼は「お願い・理由・期限」の3点を、遠慮せずに言い切る

## いま、こんな場面にいませんか

明日の会議で使う資料の作成を、ベテランの部下に頼みたい。
けれど、相手は年上だ。「お手すきのときにでも、お願いできれば……」と言ってしまう。

翌日、資料はできていなかった。相手は悪くない。急ぎだと伝わっていなかったのだ。自分の頼み方が悪かったと分かっていても、次も同じ言い方をしてしまいそうになる。

## このnoteが向いていない人

- 業務命令の扱いなど、労務の決まりを知りたい人
- 依頼を繰り返し断られるなど、問題のある状況に悩んでいる人。人事や上司に相談してください
- 年下の部下への指示の出し方を知りたい人

このnoteが扱うのは、**年上の部下に日常の仕事を依頼する工程だけ**です。

――――――― ここから有料 ―――――――

## 結論

遠慮して期限をぼかすことは、かえって相手に失礼になります。相手は、急ぎかどうかを判断できないまま、後で困ることになるからです。
**敬語は保ったまま、「お願い・理由・期限」の3点を言い切ってください**。

丁寧さは、言葉づかいで示せます。内容まであいまいにする必要はありません。年上の部下が求めているのは、遠慮ではなく、仕事として判断できる情報です。

## 手順

1. **依頼する前に、期限を日付と時刻で決める。**
2. **「〇〇をお願いできますか」と、依頼の内容を先に言う。**
3. **「〇〇に使うためです」と、理由を1文で添える。**
4. **「〇日の〇時までにいただけますか」と、期限を言い切る。**
5. **相手が難しいと言ったら、その場で期限か範囲を一緒に調整する。**

手順1を最初にするのは、話しながら期限を考えると、つい「できれば」「なるべく」が混ざるからです。

手順3の理由は、相手が優先順位を判断する材料になります。「明日の部長会議で使う」と分かれば、相手は他の仕事との順番を自分で決められます。

手順5の調整は、断られたと受け止める必要はありません。「全部は無理でも、この表だけなら9時までに出せる」のように、相手から代案が出ることも多いからです。その場で合意すれば、期限はお互いの約束になります。

## つまずきやすい箇所と、その場での対処

**命令口調になりそうで、言い切るのが怖い**
→ 「〇日までにいただけますか」と、疑問の形で言えば十分に丁寧です。言い切るのは期限の中身であって、口調ではありません。

**「今、手が離せない」と言われる**
→ 抱えている仕事の中で、どれを後に回せるかを一緒に決めます。仕事の順番を決めるのは、管理職の役目です。

**理由を言うと、言い訳のように聞こえないか心配**
→ 理由は1文に留めます。短ければ、言い訳には聞こえません。

**期限を守ってもらえないことが続く**
→ 依頼のときに、「前日の夕方に一度、進み具合を伺います」と確認の時点も伝えておきます。

## そのまま使える文例とテンプレート

**口頭での依頼**

> 〇〇さん、来期の売上見込みの資料をお願いできますか。明日10時の部長会議で使います。
> 明日9時までにいただけますか。

**言い換えの表**

| 遠慮した言い方 | 言い換え |
|---|---|
| お手すきのときにでも | 〇日の〇時までにいただけますか |
| できればお願いしたいのですが | 〇〇をお願いできますか |
| もし可能でしたら、なるべく早めに | 〇〇に使うので、〇日までにお願いします |

## 次に困ること

依頼はできるようになりました。ところが、出てきた仕事に誤りがあったとき、年上の相手に指摘するのは、依頼よりさらに気が重い。つい自分で直してしまう。
年上の部下への指摘の仕方は、続編で扱います。

# 【第4巻】年上の部下への指摘は「事実・影響・相談」の順で、その日のうちに1対1で

## いま、こんな場面にいませんか

ベテランの部下が作った資料に、数字の誤りがあった。
指摘しづらくて、自分で直して提出した。翌月、同じ誤りがまた出てきた。

また直すか、言うか。迷っているうちに、周りから「何も言えない上司」と見られている気がしてくる。

## このnoteが向いていない人

- ハラスメントや重大な規律違反への対応が必要な人。人事や相談窓口に相談してください
- 人事評価の面談で、低い評価を伝える方法を知りたい人
- 自分がミスをした側で、その後の対応を知りたい人(ミス後の信頼回復シリーズで扱います)

このnoteが扱うのは、**年上の部下の仕事の誤りを指摘する工程だけ**です。

――――――― ここから有料 ―――――――

## 結論

指摘は、人ではなく事実に向けてください。**「事実 → 影響 → 相談」の順で、その日のうちに、1対1で**伝えます。

最後を「相談」で終えるのがポイントです。「どうすれば防げそうですか」と聞けば、年齢の上下ではなく、仕事の進め方についての話し合いになります。相手の経験を借りる形になるので、ベテランほど受け入れやすくなります。

## 手順

1. **指摘することを、事実1文にまとめる。**
2. **その事実が生む影響を、1文にまとめる。**
3. **その日のうちに、1対1で話す時間を取る。**
4. **事実と影響を伝え、「どうすれば防げそうですか」と相談する。**

手順1の事実は、「資料の〇ページの売上が、元データと10万円違っていました」のように書きます。「確認が甘い」のような評価の言葉は入れません。評価の言葉は、相手の経験への否定に聞こえます。
事実だけなら、相手も確かめることができ、話が前に進みます。

手順3で「その日のうち」にするのは、時間がたつほど、指摘の理由が事実から「わざわざ蒸し返された」ことに変わってしまうからです。

## つまずきやすい箇所と、その場での対処

**自分で直した方が早い**
→ 急ぎなら、一度は直して構いません。ただし、直した事実は必ず伝えます。伝えないと、同じ誤りが繰り返されます。

**相手が言い返したり、経験を持ち出したりする**
→ 「おっしゃる通り、〇〇さんのご経験は分かっています」と認めたうえで、「今回の数字の件だけ、相談させてください」と事実に戻ります。

**人前で指摘してしまった**
→ その後、1対1で「さっきは人前で言ってしまい、すみませんでした」と一言伝えます。指摘の中身は撤回しません。

**同じ指摘が3回目になった**
→ 自分の上司にも状況を共有し、進め方を相談します。一人で抱え込む必要はありません。
共有するときも、これまでの指摘の日付と内容を事実として並べるだけにします。

## そのまま使える文例とテンプレート

**指摘の型**

| 順番 | 内容 | 例 |
|---|---|---|
| 事実 | 何が違っていたか | 〇ページの売上が、元データと10万円違っていました |
| 影響 | それで何が起きるか | 部長会議の判断が変わる可能性がありました |
| 相談 | どう防ぐか | どうすれば防げそうか、ご意見を聞かせてください |

**1対1での伝え方**

> 〇〇さん、5分よろしいですか。今日の資料の〇ページで、売上が元データと10万円違っていました。部長会議の判断に関わる数字なので、今回は私が直して出しています。
> 同じことを防ぐには、どうするのがよさそうか、ご意見を聞かせてください。

## 次に困ること

仕事の誤りは伝えられるようになりました。けれど、年上の部下から、チームの方針そのものに反対されることもあります。押し切るのか、引き下がるのか。
反対意見への向き合い方は、続編で扱います。

# 【第5巻】年上の部下に反対されたら、意見は「判断の材料」として聞き、決めた理由を返す

## いま、こんな場面にいませんか

チームの仕事の進め方を変えると伝えた。すると、ベテランの部下が言う。「それ、前にもやって失敗したんですよ」。
会議の空気が重くなる。他のメンバーは黙っている。

押し切れば、関係がこじれそうだ。引き下がれば、上司としての立場がなくなる気がする。どちらを選んでも、うまくいく気がしない。

## このnoteが向いていない人

- 会社全体の方針など、自分の判断では変えられない決定について悩んでいる人
- 指示に従わないことが続くなど、人事として対応が必要な状況の人
- 業務改善の提案を進める手順そのものを知りたい人(業務改善の提案シリーズで扱います)

このnoteが扱うのは、**年上の部下から反対意見が出たときに、受け止めて判断を伝える工程だけ**です。

――――――― ここから有料 ―――――――

## 結論

反対意見は、勝ち負けの話ではありません。**判断の材料**です。
最後まで聞き、決めるのは自分です。そして、**決めた理由を、反対した本人に返してください**。

意見が採用されなくても、理由が返ってくれば、人は「聞いてもらえた」と感じます。反対した人がいちばん嫌うのは、意見を聞き流されることです。年上の部下の「前にも失敗した」は、あなたが知らない過去の情報かもしれません。聞く価値は十分にあります。

## 手順

1. **反対意見を、途中で遮らずに最後まで聞く。**
2. **「いちばん心配なのはどこですか」と、懸念を1つに絞ってもらう。**
3. **その場では決めず、「〇日までに決めて伝えます」と期限を伝える。**
4. **決めたら、結論と理由を、反対した本人に先に伝える。**

手順2で懸念を1つに絞るのは、反対の理由がいくつも挙がると、どれに答えればいいか分からなくなるからです。いちばんの懸念に答えられれば、残りは小さな問題であることが多いです。

手順4で本人に先に伝えるのは、全体の場で初めて結論を聞かされると、反対した人が面目を失うからです。

## つまずきやすい箇所と、その場での対処

**その場で反論したくなる**
→ 反論はせず、質問だけをします。「前回は、どの点でうまくいかなかったのですか」と聞けば、反論よりも役に立つ情報が得られます。

**相手が感情的になっている**
→ 「少し時間を置いて、改めて聞かせてください」と、その場を区切ります。

**相手の意見を採用することにした**
→ 全体に伝えるとき、「〇〇さんの指摘を受けて、この点を変えました」と名前を出して感謝します。

**決めた後も、従ってもらえない**
→ 指摘のときと同じく、事実と影響で話します。それでも続くなら、自分の上司に相談します。

## そのまま使える文例とテンプレート

**懸念を絞ってもらう一言**

> ありがとうございます。前回の経験を教えていただけると助かります。いちばん心配なのは、どの点ですか。

**結論を本人に先に伝える**

> 先日の件、〇〇さんの懸念も踏まえて考えました。進め方は変えますが、ご指摘の〇〇の点は、最初の1か月で様子を見て、問題があれば戻します。
> 全体には明日の朝会で伝えます。

**判断メモ**

| 項目 | 内容 |
|---|---|
| 反対意見 | 前にも同じ進め方で失敗した |
| いちばんの懸念 | 繁忙期に手順が増えると回らない |
| 判断 | 進め方は変える。繁忙期の前に一度見直す |
| 理由 | 普段の作業時間を減らす効果の方が大きいため |

## 次に困ること

反対意見を受け止められるようになると、自分からチームの仕事の進め方を変える提案をする場面も増えます。改善を提案し、試し、定着させる手順は、別のシリーズで扱っています。
